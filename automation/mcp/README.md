# MCP/应用工具在这个项目里做什么

[自动化总览](../README.md) · [仓库CLI](../online_judge/README.md)

这里记录工具接入关系，帮助读者迁移流程。仓库当前提供的是Python CLI与文档，**没有独立MCP server，也不提供一份可直接安装的MCP服务配置**。

## 实际使用过的能力

| 能力 | 在支持的Codex客户端中的工具示例 | 仓库替代/执行入口 |
| --- | --- | --- |
| 创建、读取和更新周期任务 | mcp__codex_app__automation_update | 客户端自己的调度；提示词模板在本目录上级 |
| 读取账户用量窗口 | mcp__codex_app__get_usage_limits | 不存在通用的本地推断；由账户客户端提供 |
| 读取线上成绩、恢复判分 | CLI经授权执行 | judge.py latest / wait |
| 一次上传 | CLI经本人授权执行 | judge.py submit |
| 低频榜首参考 | CLI共享缓存 | judge.py ranking |
| 离线验证 | 本机命令执行工具 | dev/run.py、local_judge.py |

工具名来自使用时的应用接口，其他客户端可能不同。先通过客户端的能力发现机制确认可用工具，不能把上述名字当成通用MCP协议的一部分。

## 学习接入时的关键边界

调度工具决定何时继续，CLI决定具体怎样冻结、上传和绑定作品。不要让MCP服务绕开既有JobStore、提交锁和两次终分确认，也不要把浏览器Cookie作为模型上下文或分享配置。

未来若实现独立MCP server，应先封装只读能力（任务状态、离线报告、缓存榜首），再提供明确区分的提交动作；仍复用既有CLI/状态存储，避免另写一套重试上传逻辑。目前该server属于后续扩展方向，不能在README中标成已完成。
