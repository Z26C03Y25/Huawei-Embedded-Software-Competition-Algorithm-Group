# 初筛区间、完整精扫与右探重试

2026-10-31，按用户提出的结构实现的线上实验。父版为正式212320；候选名`interval_sweep_retry_v2`。实测结果及是否采用见[实验记录](../../data/experiments/blackbox_20261031/README.md)。

初筛保留已评分的前探策略，在其观测上预测候选中心。能得到局部模型顶点时用它作建议，同时区间必须包含原始已读最佳点附近；无法拟合时以已读最佳点为中心。

精扫枚举候选区间内每个整数下标，复用缓存，只对未读点实际查询。整段不满足查询和路线预算时不启动该批，首轮回退至已评分的精修策略。完整扫过只代表局部核查完成，不能证明全局最高峰位于这个区间。

首轮精扫之后预留49次：最多16次右探、最多32次二次精扫、1次最终停车；并审核首轮扫描结束后还可承担最多三次转向。右探中每次读取还重新检查后续精扫和停车余量，不把剩余额度全用在探路。

容错触发条件：精扫后的已读赢家距区间边界不超过2格。左侧开放则第二轮扩大左侧覆盖；右侧开放则继续右探。出现严格更高的原始值后围绕新候选再精扫，最多两轮。未找到更高值时保留原赢家，最终真实查询停车；不要求重新读取缓存来恢复旧候选。

右探使用原前沿逻辑，并加入当前候选相对的`best+196`限制。它给目标在该点左侧3格的假设留出冗余余量，不能保证未知真实R；仍可能阻断远端更高峰。它只在区间边界未解决后的重试启用，与此前已淘汰的全局限制不同。

首轮半径为8格，第二轮扩为16格，且合并模型中心附近范围；这些是待正式反馈检验的首版选择，不是从题面推出的真实峰宽。最高点处于区间内部时，远端仍可能藏有更高峰，因此“失败后右探”只覆盖可检测到的边界失败，不能保证所有漏峰都能自诊断。

下一步若分组检验，应固定同一父版，分别按互斥N范围启用整个控制器；不能直接叠加不同机制的总分增益。任何低于212320的候选都不替换入口源码。

## 正式反馈

首版全N为206770（相对212320为-5550），仅中N启用为211817（-503），均未采用。进一步将初筛提前到两次下降后交接，并在精扫后进行有限右侧审计的`interval_early_handoff`为159964（-52356），亦未采用。

这些总分不能恢复实际零分个数或具体错误轨迹。它们否定了当前实现的净收益；尤其不能用“区间内部最高点”作为全局命中证据。阶段交接需要更可靠的峰区间支持，继续右探也需要在远端探索与早峰冗余之间作明确决策。
