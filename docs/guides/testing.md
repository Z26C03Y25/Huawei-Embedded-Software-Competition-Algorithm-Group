## 默认离线检查

```bash
python dev/run.py check
```

依次检查文档本地链接与归档哈希、线上工具的离线模拟测试、判题器边界、合成对比工具，自动研究上限/证据/恢复门槛，以及评分归档和求解器核心回归。需要g++，不启动浏览器、不安装依赖、不访问平台。

## 性能诊断单独呈现

```bash
python dev/run.py diagnostics
```

该命令运行test_strategy_solver.py的全部原始断言。当前203239版本仍有已知失败，没有删除或放宽它们。最新15个测试方法中有9个失败断言，包含新增多尺度纹波反例；见[本地研究](../daily_research/2026-10-26-local-first.md)。历史完整根测试曾有8个子用例断言失败，覆盖4个测试方法：

| 失败类型 | 子用例数 | 含义 |
| --- | ---: | --- |
| 长平坦前缀后的远端峰 | 1 | 合法交互，但目标遗漏 |
| 宽平台内更早的原始尖点 | 1 | 未查到201点，停车不合格 |
| 中等独立噪声峰 | 3 | 真实冗余或停车不合格 |
| 旧平坦期限必须恰为199 | 3 | 当前取144且仍正分，与旧策略参数断言不一致 |

新版本可能改变失败集合，以实际报告为准。这些记录用于理解启发式取舍，不能用它们估算官方零分用例数量。

## CI如何呈现

[CI配置](../../.github/workflows/ci.yml)分成离线工具检查、C++核心回归和策略诊断。前两者作为阻断检查；策略诊断原样运行，已知失败步骤允许继续，并在运行摘要中显式标出结果。CI通过只代表所列核心检查通过，不声明全部策略断言通过。

仓库重构时只在当前本机验证命令；配置需要推送后才能在GitHub环境实际运行。Windows和Linux工具测试配置不等于已经完成所有平台实测。

## 如何提交一个性能反例

提供完整曲线或可复现生成器、种子、源码SHA256、参数、查询位置、原始回复，以及Q/M/O/R/d/零分原因。报告同时说明修复了哪些例子、增加了哪些失败，不只报一个合成总分。

时限、EOF、输出格式等协议检查应保持严格。改策略参数时，先理解旧断言的意图；不能以“新代码不满足”为理由删掉不利案例。
