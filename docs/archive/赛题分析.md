# 自动聚焦赛题分析与版本对比

> 历史说明：本文记录旧版实现和实验。当前 main.cpp 已按用户要求改为分层算子策略，版本现状、预算控制及运行模式请以《策略实现说明.md》《策略验证结果.md》为准。

依据仓库内《2026华为嵌入式软件大赛算法组赛题.pdf》。本题是带电机移动成本的交互式、数据驱动寻峰题；题面没有提供单峰、峰宽、斜率或噪声上界，因此各版本均采用启发式，不能承诺任意合法数组都得分。

## 1. 正式接口与评分

正式数据长度为 `400 <= N <= 1000`，元素范围为 `[0, 2^31-1]`。程序先读 `N`，之后每次向标准输出写一个合法下标并立即刷新，再从标准输入读该位置的清晰度。结束时输出 `DONE`，退出码为 0。最终停车位置是最后一次查询下标，`DONE` 不携带位置。

```text
checker -> program: N
program -> checker: idx
checker -> program: value
... repeat ...
program -> checker: DONE
```

每行必须为 ASCII、以换行结束、长度不超过 64 字节；调试信息只能写标准错误。提交单个 `main.cpp`，正式编译参数为 `g++ -O3 -Wall -std=c++17`。题面中的长度 12 示例用于说明协议，不是正式长度范围。

目标主峰 `p*` 是数组原始值的全局最大值位置。多个位置同为最大值时，按以下顺序选择：

1. `|2*i - (N-1)|` 更小，即更接近数组中央。
2. 距离仍相同则下标更小。

平滑后的峰值、较宽的峰、较早遇到的峰，都不能替代这个规则。实现中的去噪只服务于搜索决策，最终候选仍按原始值和平局规则比较。

设查询位置序列为 `x1, ..., xQ`，初始位置 `x0 = 0`，则：

```text
movement    = sum(abs(xk - x(k-1)))
search_time = Q + movement
redundant   = max(0, max(xk) - p*)
d           = abs(xQ - p*)
```

振荡次数是移动方向发生反转的次数，第一次读取不计振荡。查询可以跳跃，但跳跃的距离仍计入移动成本。缓存命中只是在程序内取值，不会让真实电机移动；若需要回到已采样的最佳位置，必须再次输出该下标并读取应答，这也增加一次查询。

只有满足 `d <= 3` 且未触发下表阈值时，单用例才可能获得正分：

```text
score = max(0, 3000 - 200*d - search_time - oscillation - redundant)
```

| 项目 | 可得分范围 | 触发 0 分的边界 |
| --- | --- | --- |
| 查询次数 | 最多 199 次 | `Q >= 200` |
| 振荡次数 | 最多 6 次 | `oscillation >= 7` |
| 冗余步数 | 最多 199 | `redundant >= 200` |
| 停车误差 | 最多 3 | `d > 3` |

每用例还受 10 秒和 512 MB 限制。总分为 102 个用例得分之和。停错峰或超过上述计分阈值属于合法完成但该例 0 分；协议错误、超时等会使整份作品失败。不能为了节省最后一次查询而把电机停在错误位置，也不能把 200 次查询误当作可用预算。

## 2. 为什么不能直接套用二分或三分

题面明确包含噪声假峰、运动干扰、前景和背景双峰，没有给出离散单峰条件。比较两个位置的值并不能排除某一侧存在更高的峰，因此二分爬坡、三分或黄金分割都没有全局正确性保证。

更根本地，有限查询无法保证任意合法数组都正确。考虑一次搜索的所有应答都是 0；即使进行了 199 次不同下标查询，在 `N >= 400` 时仍至少有 201 个位置未查询。最终停车位置的 `±3` 范围最多只有 7 个位置，因此必然能在该范围外选到未查询位置 `p`。令 `a[p] = 1`、其他位置为 0，程序看到的全部应答保持不变，却停在距唯一主峰超过 3 的位置。这给出了一个合法的失败数组。随机化可以改变失败分布，但也不能给出对所有数组的必然成功保证。

硬冗余限制同样不能仅靠“离已观测最佳点不超过某个距离”来证明。举例：数组 A 仅 `a[0] = 1`，其他值均为 0；要在 A 上保持冗余小于 200，就不能到达下标 200 或更右处。把某个未探测的右侧位置改为 2 得到数组 B，程序在停止前收到的应答相同，却无法聚焦 B 的右侧主峰。正确聚焦与硬冗余限制之间需要依赖实际曲线特性作取舍，不能由题面给出通用保证。

因此，这道题的关键是从真实数据中判断何时足以停止右探，以及如何用少量查询覆盖有竞争力的峰；不是证明任意整数数组都能在 199 次内求出全局最大值。

## 3. 首版实现（已归档）

`versions/main_v1_154353.cpp` 采用“向右粗搜、反向局部精修、返回最佳点”的轨迹。用户确认此版本的正式评测总分为 **154353**，平台不提供逐例反馈。此分数不能反推出具体哪些用例丢分。

1. 从 0 开始单调向右采样，固定间隔为 8。`N=1000` 时含右端点最多查询 126 次，给精修预留预算，同时减少大步跳过窄峰的机会。
2. 用最近 3 个粗采样值的中位数观察趋势，用所有已观测三点插值残差的中位数估计波动 `noise`。使用整个历史，可以避免噪声基线中一小段平静区把噪声估计突然降得过低。若 `smooth_peak-floor >= max(1,8*noise)` 或 `bestValue-floor >= max(1,16*noise)`，视为存在显著峰；后一个条件保留原始值极高的窄峰。软停止要求：峰足够显著；连续 4 次没有刷新平滑峰；离平滑峰和原始最佳位置均至少 96；下降量超过 `max(1,3*noise,0.1*(smooth_peak-floor))`；当前原始值和平滑值都没有超过噪声门槛的回升。其中 `floor` 为已观测最小原始值。
3. 当峰足够显著，或迄今采样完全相等时，另以相对“已观测原始最佳位置”前探 160 为停搜条件。该条件只在采样位置上检查，实际可能多走不足一个步长。它控制过度右探的倾向，不等于对真实主峰的冗余保证。没有显著峰的噪声基线会继续搜索。完全相等时，已观测最佳点随平局规则向中央移动，因此能正确处理常数数组；但这会错过更晚才出现的右侧峰。
4. 在粗采样序列中找局部极大候选，仅保留原始值不低于 `bestValue - 0.5*(bestValue-floor)` 的候选，避免为远处低基线来回移动。按原始值和正式平局规则排序，选择最多 3 个候选的 `±16` 邻域。邻域裁剪到已探测区间，精修新增查询预算为 `min(100,198-粗查询数)`；一个窗口预算不足时跳过，不截断窗口。
5. 把所选邻域的未采样下标合并，按从右到左的顺序逐点查询。窗口之间仍有实际移动成本，但不因窗口排名顺序来回折返。
6. 若当前位置尚非已观测最佳位置，最后真实查询一次最佳位置完成停车，再输出 `DONE`。常规查询最多使用 198 次，保留一次停车预算，总查询最多 199 次。

整个轨迹先向右，再向左精修，最后返回最佳点，因此最多发生 2 次方向反转。这个上界来自查询顺序，不依赖峰形。查询次数也有显式上界。能否找到真实主峰、真实冗余是否小于 200，则依然取决于数据。

代码也支持题面长度 12 示例等小输入：`N <= 198` 时逐点单调扫描并返回精确最佳点；这不是对正式长度范围使用全扫描。

## 4. 已知局限与验证方式

首版可能在以下结构上失败：粗网格间出现很窄且很高的峰；长平坦区之后远处才出现主峰；先遇到明显局部峰、下降后更远处又有更高峰；噪声导致粗候选排名失真，真实主峰邻域未进入最多 3 个精修窗口。全局最大值若是孤立尖刺，平滑趋势尤其不能替代原始值目标。

当前仓库未提供正式的 102 条真实清晰度数组。合成用例只能验证协议、查询预算、轨迹计数，以及在指定峰形上的行为；它们不能推算正式总分或真实场景成功率。测试报告应把协议错误与合法 0 分分开，并保留失败曲线和查询轨迹。

拿到真实数据后，优先按平坦区、峰宽、双峰间距、次峰高度和噪声水平分组；分别统计停车误差、查询数、移动距离、反转和真实冗余。再用独立留出的曲线验证以下参数：粗采样间隔、持续下降门槛、噪声系数、前探距离和精修窗口数。若窄峰漏检占主因，应增加粗搜覆盖；若冗余超限占主因，应改进早停；若主峰已经命中但分数偏低，再压缩移动和精修查询。不要只在同一组合成峰上反复调参后宣称真实性能提升。

## 5. 首版本地验证结果

2026-10-24，使用 `g++ -O3 -Wall -Wextra -Wpedantic -std=c++17` 编译，无警告；判题器的 15 项单元测试全部通过。扩展曲线集使用种子 `2026`：

| 合成曲线分组 | 用例数 | 合法完成 | 正分 | 零分 | 合成总分 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `standard`（样例、平滑峰、边界、少量噪声及数值边界） | 50 | 50 | 47 | 3 | 106658 |
| `challenging`（双峰、尖峰、平台、高噪声、无结构数组等） | 38 | 38 | 27 | 11 | 60837 |

这 88 次交互均无协议错误或超时；本次观测最大查询数 198、最大反转数 2。3 个 `standard` 零分均来自长量化平坦区后才起峰的随机平滑曲线；`challenging` 零分来自远隔的更高第二峰、未采样尖峰及无结构数组。`standard` 是曲线生成标签，不代表官方分类或保证通过的测试。

题目 PDF 中的示例轨迹在判题器测试中复现为 2984 分；本算法对同一数组使用完整的小数组扫描，实际轨迹得分为 2961，两者不是同一条查询轨迹。运行说明见仓库 README；`build/extended_v1_results.json` 保存首版重新验证的查询轨迹和全部指标。

## 6. 第二版的改动与依据

当前 `main.cpp` 是第二版，正式分数待重新提交。用户给出的其他参赛者分数为 215968；没有该实现或逐例结果，不能据此确认某一种算法就是差距来源。

首版的局部窗口分配存在可复现的问题：长度 1000，其余值为 0，`[200,360]` 全部为 10000，另令 `a[224]=10090, a[248]=10089, a[272]=10088, a[347]=10100`。三个局部窗口都可能堆在同一宽峰左侧，漏掉 347；而粗搜后剩余查询本来足以覆盖整个竞争区。另一反例是 `[200,400]` 为 10000，`a[201]=10100, a[336]=10090`：以粗采样最佳位置 336 为唯一前探锚点时，首版可能先越过真实主峰 200 格再回头。第二版对这两例均能精确停车，得分均为 2070。

第二版保持单个可提交源文件，作出以下修改：

1. 粗步长由 8 改为 12，长度 1000 最多约 85 次粗采样，为宽峰逐点覆盖释放查询预算。代价是更窄的峰可能落在网格之间。
2. 波动估计改为按实际下标间距作三点线性插值后的残差中位数，右端最后一个不等距区间也按实际距离计算。
3. 显著性条件为 `smooth_peak-floor > max(1,8*noise)` 或 `bestValue-floor > max(1,16*noise)`。无显著峰时继续探索完全平坦区域，避免首版的中央附近早停漏掉晚起右峰。
4. 在不存在超过噪声门槛的回升、已离开最佳点至少 36 格、下降超过 `max(3*noise,0.04*contrast)` 时结束粗搜。相比固定 96 格前探，这能减少单峰命中时的移动和冗余成本，但可能更早错过第二峰。
5. 将不低于 `bestValue-max(3*noise,0.04*contrast)` 的已观测最左位置作为竞争区左边界。已有显著峰且右探距离达到 168 时先精修；下一次粗跳会使距离超过 180 时也不继续。它保护的是模型中的竞争区，仍不是对任意隐藏主峰的冗余保证。
6. 精修门槛为 `bestValue-max(1,3*noise+0.02*contrast)`。对端点至少一个达到门槛的粗区间，考虑所有内部位置，并用线性插值的原始值排序。最佳点 `±16` 内及跨越门槛边界的区间优先，其余按预测值排列。用完 `198-已查询数` 的剩余预算，保留一次真实停车查询。
7. 所有精修点最后按下标递减查询，维持最多 2 次反转。最终仍比较原始值和中央平局规则。

另外保留 `versions/main_v2_conservative.cpp`：继续使用首版的主要停搜规则，将剩余查询按竞争区覆盖重新分配；区间过宽时先中等密度补采，再依据新结果细采。这一备选在本次独立对比中没有新增结构类零分，但提升较小，最多 3 次反转。默认 `main.cpp` 采用总分更高的第二版候选。

## 7. 对比实验与明确退化

对比工具 `tools/compare_solvers.py` 使用 14 类曲线，混合三角、Lorentz、非对称、分段线性、平台和高斯形状。每条数组、查询轨迹、程序 SHA256 都保存到 JSON，可以直接回放；随机无结构数组和单点尖峰另计。生成器没有读取候选程序的决策或参数。

候选比较使用种子 2026；确定候选后，再用种子 73 和 9109 各 144 条曲线作独立检查，合计 288 条，所有交互合法：

| 分组 | 曲线数 | 首版总分 | 第二版总分 | 差值 | 首版/第二版零分数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 结构类（含常数数组） | 248 | 480698 | 501931 | +21233 | 39 / 42 |
| 随机数组、单点尖峰 | 40 | 10839 | 5880 | -4959 | 35 / 36 |
| 全部 | 288 | 491537 | 507811 | +16274 | 74 / 78 |

结构类逐例比较为 199 胜、14 平、35 负；救回 25 个原先零分的用例，也新增 28 个零分。新增零分中，20 个是完全常数数组、7 个是近距离双峰、1 个是宽噪声峰。总分增加不等于成功率在所有分类上都增加。

完全常数数组必须特别说明：第二版为发现晚起峰而继续搜索到右端，真实主峰仍按平局规则位于中央，因此触发冗余 200 的零分阈值。这是当前取舍；更稀的粗网格也可能漏过极窄的峰。这些结果只说明候选在所列合成分布上的表现，**不证明正式分数已经提升，更不能据此承诺 215968**。

后续优先取得第二版的正式总分，再与已确认的 154353 成对比较。只有总分反馈时，每轮保留确切源文件，避免同时改动多套策略后无法判断有效方向。

最终检查：C++17 编译无警告，判题器、对比工具和求解器回归共 32 项测试全部通过。原有 88 条扩展曲线也重新成对运行：首版 167495 分、第二版 179837 分，均无交互错误；其中第二版 `standard` 50 条全部正分，`challenging` 有 12 条零分。这是另一组合成结果，同样不替代正式成绩。
